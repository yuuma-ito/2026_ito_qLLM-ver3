# seed 0〜19の補完実験と統合方針

2026年10月12日のユーザー指示に基づき、残り2モデルのseed 0〜9を補完する。元実験の記録・保存設定は保持し、統合集計を別の保存先に作成する。

| 実験 | モデル | seed | 件数 |
| --- | --- | --- | ---: |
| `shared_three_models_full_20261008T103231611899Z` | qwen3.5:4b、gemma4:e4b-it-qat、qwen3.5:9b | 0〜9 | 1,500 |
| `shared_five_models_full_20261010T041019864060Z` | 上記3モデル＋qwen2.5-coder:7b、gemma3:4b | 10〜19 | 2,500 |

| 統合後 | 5モデル | 0〜19 | 予定5,000 |

各モデルは10タスク×20 seed×5条件で1,000件となる。5条件はbaseline、self_refine、execution_feedback、self_debugging、preventive_spec。温度0.7、最大修正3回、reasoning_effort=none、max_tokens=1024、timeout_sec=600、同時要求1件とする。初期生成を共有する条件があるため、5,000件を独立した5,000回の生成とは扱わない。

## 既存実験の確認

保存設定・manifest・automation reportを比較したところ、タスク、介入条件、生成設定、プロンプトのSHA-256、Python・Qiskit・Aer等の環境、接続回復設定は一致した。共通3モデルのdigestも一致している。ローカルサーバ上の補完対象2モデルのdigestは、既存5モデル実験に記録された値と一致した。追試の開始前にも条件・digest・予定グリッドを確認する。

旧実験の実行時コミットは `9c6f952b41ac661bb42bb1ffe4d3f37282260658`、追加実験は `9c1833eba6020369247358c04e462e0dc1982705`。この間にschema 2.0から2.1への変更と、実行段階・例外型の記録、エラー分類の変更がある。`diagnose()`はエラー分類を診断文に使うため、プロンプトのテンプレートが同じでもexecution_feedbackとself_debuggingでモデルに渡す内容が変わり得る。保存済みの再分類は、過去にモデルに渡した診断文を変更しない。

したがって、統合値は混合手順の記述的結果として扱う。`summary_by_source.csv`に実験別・モデル別・条件別の件数と成績を残し、モデル差・seedブロック差・実施時期・処理差を混同しない。単一の手順による介入効果や統計的有意差を断定しない。過去の診断文への影響を厳密に除く場合には、同じハーネス版での別追試が必要であり、今回の補完実験では既存3モデルの記録を置き換えない。

## 介入カタログの分母修正

追加5モデル実験の生データ2,500件ではbaselineのL2失敗数は288件だったが、古い介入カタログの分母は137件だった。カタログは通常の実験終了時の集計処理に組み込まれておらず、途中の集計が残っていた。

今回、元の生データを変更せず、全件から3種類のカタログを再生成した。4介入すべての分母は288件になり、生データと一致した。旧3モデル実験も再生成して分母161件との一致を確認した。今後は5条件そろった実験の終了時にカタログを生成し、公開前に全カタログの内容を生データから再計算した値と照合する。固定済みの旧発表資料とその出典は当時の状態として保持する。

## 実行と公開

```bash
.venv/bin/python -m scripts.automate_experiment --config configs/shared_two_models_seed0_9_full.json --new-run --pool-config configs/shared_five_models_pool.json
```

新しい時刻付き実験IDを一度だけ確定する。再開時にはその実験の保存設定を指定し、再び`--new-run`を付けない。実験レポートに出典を事前登録する場合は、`prepare_config(..., new_run=True)`で時刻付き設定を保存してから、同じ保存設定でラッパーを起動する。

補完実験の全件記録・sanity・API障害・カタログ整合性を確認した後に統合する。統合処理は各出典も再検証し、重複・欠落・予定外記録、保存設定の違い、モデルdigestの違いを拒否する。検証や統合に問題が残る場合は自動公開しない。

統合先は `results/shared_five_models_pooled_seed0_19/`。公開用CSV、出典・ハッシュ・保存設定を含むmanifest、sanity report、automation report、説明文を保存する。統合用JSONLは一時的に`.cache/`で作成し、公開先には保存しない。CSVから生成コード差分の列を除き、秘密情報や生成コードを統合成果物に含めない。

ラッパーが検証後のコミット・プッシュを担当する。コミットメッセージは日本語の短い概要と変更点の箇条書きにする。
