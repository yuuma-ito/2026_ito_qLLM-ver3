# 分布評価の測定結果の扱い

2026-11-04追記：以下の実装変更と実施状態は2026-10-14の再評価前の記録である。その後、[全5,000条件・9,517 roundの再採点](analysis/reevaluation_full_20261014T141718Z/README.md)と[293ケースの部分追試](analysis/reevaluation_followup_20261015/README.md)が完了した。現行結果は[到達経路](analysis/reachable_rescues_20261016/README.md)と[B4追加実験](analysis/independent_4_completed_20261022/README.md)を参照する。末尾のNO-GOは当時の準備判定であり、現在の未完了状態を示すものではない。

現行v4は指定入力の出力と所定の構造条件を判定し、課題文の全条件や任意入力での算法同値性は保証しない。共通プロンプトの測定禁止を強制しない課題で、測定を含む主L3成功がある。[実例と評価範囲](analysis/reevaluation_followup_20261015/specification_review.md)を参照する。新たな[参照適合性検査](reference_conformance.txt)は別仕様として実装・テストしたものであり、既存L3・固定設定・停止経路を変更しない。保存コードへの適用と成功数の再集計は未実施である。

2026-10-14に採用した `qubit_readout_v2` の測定処理を保持し、評価器の最新版を `evaluation_policy_v4` とする。測定先の古典ビットから量子ビット順 `q[n-1]...q[0]` の分布を取り出し、未使用古典ビットの有無や測定先の配置だけで出力一致の判定が変わることを防ぐ。

## 採用した処理

- 測定のない回路には、評価器が全量子ビットを新しい古典レジスタへ測定する。その追加レジスタの結果だけを比較する。
- 明示的な測定がある回路では、各量子ビットの測定先を調べ、量子ビット順へ戻して比較する。測定に使われない古典ビットの値は合算する。
- 全量子ビットの一意な終端測定を要求する。部分測定、量子ビットの再測定、古典ビット上書き、測定後の量子操作、古典制御は `evaluate / interface_mismatch` として拒否する。
- 出力文字列の一律反転や一律の切り捨ては行わない。量子ビットの状態そのものが逆なら、従来どおり出力不一致・ビット順序誤りの対象となる。

分布の一致はL2、構造条件も満たす成功はL3である。既存の `expected_classical_bits`、`expected_measurement_count`、`measurement_required`、ゲート数などの構造条件は引き続き確認する。今回の変更は状態ベクトルによる比較には適用しない。

## タスクの仕様

現在の分布タスクは、全量子ビットの出力をQiskitの量子ビット順で比較する。古典ビットの配置を自由にしても、量子ビット順の出力が一致すればL2は成功となる。

将来、特定の古典ビットへの測定配置そのものを要求するタスクを追加する場合は、その対応を検証する構造条件を追加する必要がある。現在のビット数・測定数の構造条件だけでは、個々の測定先の配置を検証しない。

## 実験の版と過去の結果

新しい実験のmanifestに `evaluator_version` と評価器・測定処理のソースhashを記録する。旧評価器で一部だけ記録された実験への追加生成は停止し、新しい保存先を使う。旧実験が全件記録済みの場合は、保存された判定を使う検証・集計の再開を許可する。

2026-10-14の変更時点では、検証済み5,000件と固定スナップショット、過去の成功率・救出数は元の判定を保持し、まだ新評価器で再評価していなかった。その後の再採点も元の結果とは別の保存先と比較資料に記録した。新旧の評価器による数値を同一条件として統合しない。

2026-10-14の測定処理の更新作業自体では、LLMの追加生成や既存生成コードの一括再評価を行わず、Pの予防的プロンプトも変更しなかった。

## 確認結果と実装

[出力表現への感度確認](analysis/output_representation_20261014/README.md)で、同じ正しいQPEが未使用古典ビット3個により `1010` から `1010000` へ変わり、旧比較では失敗することを再現した。新処理では `1010` として成功し、誤ったQPEは不合格を維持する。

実装は [harness/readout.py](../harness/readout.py) と [harness/evaluator.py](../harness/evaluator.py)、版の記録は [harness/experiment.py](../harness/experiment.py)、旧実験への追加生成防止は [scripts/run_experiment.py](../scripts/run_experiment.py)。テストは [tests/test_canonical_readout.py](../tests/test_canonical_readout.py) にある。

## 評価方法全体の点検による更新

[評価方法の点検](analysis/evaluation_methods_20261014/README.md)により、状態ベクトルの全体位相補正の符号を修正した。シミュレータとtranspileのseedを42、shotsを8,192としてmanifestに記録する。構造判定のゲート数からbarrierを除き、未束縛パラメータ・状態ベクトル回路の測定・範囲外の構造をinterface_mismatchとして分類する。

分布だけでは相対位相を検出できず、ゲート数範囲だけではアルゴリズムの手順を保証しない。後続の再評価では主判定と補助検査を分けて記録した。2026-10-14の評価器更新作業自体では既存5,000件の再評価は行っていなかった。

## 文献と公式仕様に基づく追加監査

[追加監査](analysis/literature_reliability_20261014/README.md)で、部分resetのStatevectorが乱数で選ばれた分岐となることを確認した。v4の主状態ベクトル評価はOperatorでユニタリ性を確認し、全ゼロ入力に対応する列を返す。非ユニタリ・古典操作はinterface_mismatchとして拒否する。DensityMatrixの補助評価を自動で主判定へ置き換えない。

主判定のこの変更と旧版との差を保存する。2026-10-14時点では、隔離実行、専用中断再開、補助オラクルの確認が終わるまで本番再評価をNO-GOとしていた。[準備条件の解消](analysis/reevaluation_completion_20261014/README.md)後に本再評価と必要な部分追試を実施した。
