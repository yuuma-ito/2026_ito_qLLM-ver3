# 評価器の出力表現への感度確認

2026-10-14に、LLMを呼ばずに作成した確認用回路19例をAerSimulatorで実行した。未使用古典ビットと測定先の配置だけで、現在の出力比較が不一致になることを確認した。現行評価器と保存済み5,000件の評価値は保持する。

## 確認した結果

| 回路 | 現行の出力 | 現行L2 | 測定先に基づく比較候補 |
| --- | --- | --- | --- |
| 正しいQPE、未使用古典ビットなし | 1010 | 成功 | 成功 |
| 同じQPE、未使用古典ビット3個 | 1010000 | 失敗 | 成功 |
| 正しい2ビット回路、未使用古典ビット3個 | 10000 | 失敗 | 成功 |
| 正しい2ビット回路、測定先を逆に配置 | 01 | 失敗 | 量子ビット順へ戻すと10で成功 |
| 誤った2ビット回路、通常の測定先 | 01 | 失敗 | 失敗 |
| 誤ったQPE、未使用ビットなし／3個 | 複数の誤った出力 | 失敗 | 両方とも失敗 |

19例の内訳は正しい回路10例、誤った回路6例、測定対応が曖昧な回路3例。正しい10例のうち、現行比較で失敗した7例が比較候補では成功した。誤った6例はすべて不合格のままで、部分測定・測定先の上書き・測定後の量子操作の3例は比較候補で拒否した。これは制御された少数の確認例であり、あらゆる誤回路に対する保証ではない。

L2は分布の一致だけを比較している。構造条件を含むL3や、既存実験の成功率・救出数は再計算していない。

## 原因と比較候補

現行の[harness/evaluator.py](../../../harness/evaluator.py)は、回路内に測定がない場合に`measure_all()`で新しい古典レジスタを追加し、`get_counts()`の文字列から空白だけを除く。そのため、元から存在した未使用古典ビットの0も出力に残る。明示的な測定がある場合は、その測定先の古典ビット順のまま比較する。

[Qiskitの公式仕様](https://qiskit.qotlabs.org/docs/api/qiskit/qiskit.circuit.QuantumCircuit)では`measure_all`の`add_bits`は既定で真であり、[ビット順序の説明](https://qiskit.qotlabs.org/docs/guides/bit-ordering)では表示文字列の右端がビット0に対応する。今回のローカル実行でもこの動作を確認した。

比較候補は各測定の「量子ビット→古典ビット」の対応から、出力を`q[n-1]...q[0]`へ戻し、測定先以外の古典ビットを周辺化して合算する。単純な末尾切り捨てや一律のビット反転は使わない。対象は全量子ビットを重複なしで終端測定する回路に限定し、部分測定、古典ビット上書き、同じ量子ビットの再測定、測定後の量子操作、古典制御を拒否する。

この処理は量子ビット順で出力を評価する候補である。タスクが古典ビットへの特定の配置を要求する場合には、その配置自体を構造条件で確認する必要がある。測定先が逆でも量子ビット順へ戻すことを、すべてのタスクで正しい仕様とは扱わない。

## 保存済み結果の確認

検証済み3実験の固定スナップショットに対応する生データを読み、保存されている分布だけを確認した。分布が保存されたround行2,880行のうち、タスク指定の量子ビット数と出力文字列の幅が異なる行は619行。すべて元のL2は未達だった。共有初期生成がB・R・F・Dに重複記録されるため、独立した619回の生成を意味しない。

| タスク | 幅が異なるround行 |
| --- | ---: |
| DJ constant | 170 |
| DJ balanced | 125 |
| BV | 131 |
| Grover | 59 |
| Bell | 66 |
| GHZ | 37 |
| QPE | 31 |

出典別は3モデル実験169行、5モデル追加314行、2モデル補完136行。条件別はB 37行、R 136行、F 139行、D 108行、P 199行。全件の出典・モデル・タスク・seed・round・保存判定・コードhashと分布を`stored_width_mismatches.csv`に保存した。

幅の違いには、未使用古典ビット以外に、部分測定や量子ビット数の誤りなども含まれ得る。保存された文字列だけでは測定先の対応を確定できず、619行を一括して成功へ変更することはできない。保存されたLLM生成コードは今回実行していない。

## 改善の判断と次の作業

出力表現への感度を減らす改善は必要と判断する。まず測定のない回路への評価器追加測定で生じる余分な古典ビットを分離することが、明確な改善対象である。明示的測定については、量子ビット順で評価するか、指定された古典ビット配置を要求するかをタスク仕様に記載する必要がある。

今回の比較候補は[scripts/check_output_representation.py](../../../scripts/check_output_representation.py)内に置き、本番の評価器には適用していない。次に評価仕様を固定し、評価器の版を分けて既存結果との比較を行う。新しい版の判定は別資料に保存し、元の判定を保持する。Pの古典ビット数に関する注意事項も、共通の測定禁止指示と整合するよう見直し対象にする。

## 再現方法と出典

```bash
.venv/bin/python -m scripts.check_output_representation \
  --out-dir docs/analysis/<新しい保存先>
.venv/bin/python -m pytest -q tests/test_output_representation.py
```

各回路8,192 shots、simulation・transpile seedは42。QPEはリポジトリの既存の正しい／誤ったmock回路を利用し、他は手作りの確認用回路。固定出典・生データhash・実行環境の版・評価器と確認スクリプトのhashは`manifest.json`、全19例は`controlled_cases.csv`、確認項目は`sanity_report.json`に保存した。API呼び出しと新しいLLM実験は行っていない。
