# FとDの使い分けを検討するための観測結果

検証済み5,000件から、同じ初期コードに対してFだけがL3へ救出した42件、Dだけが救出した42件を抽出した。全体の初期未達582件、共通救出149件、どちらも未達349件も分母として保持した。[全表と修正履歴](README.md)、[84例の一覧](discordant_cases.csv)、[コード確認の根拠](case_observations.json)を参照。

## 失敗類型ごとの違い

| baseline類型 | 初期未達 | Fのみ | Dのみ | Fの全救出 | Dの全救出 |
| --- | ---: | ---: | ---: | ---: | ---: |
| import_error | 271 | 8 | 18 | 55 | 65 |
| syntax | 68 | 9 | 2 | 25 | 18 |
| build_error | 106 | 11 | 11 | 57 | 57 |
| wrong_output | 102 | 11 | 9 | 40 | 38 |
| interface_mismatch | 32 | 3 | 2 | 14 | 13 |
| qubit_count_mismatch | 3 | 0 | 0 | 0 | 0 |

import失敗ではD、構文エラーではFの救出が多かった。モデル別に見ると、importの差は主にqwen3.5:4b（F 45/91件、D 56/91件）に現れている。構文の差はgemma4（F 16/17件、D 11/17件）で大きかった。全モデル共通の使い分けとして確定せず、これらのモデル・失敗類型を具体例確認の候補とする。

wrong_outputの全体差は小さく、モデルで方向が異なる。qwen2.5-coderではF 9/28件・D 6/28件、qwen3.5:9bではF 17/29件・D 20/29件であった。回路構築の全体救出は同数であり、失敗分類だけでは条件を選べない。

## タスクごとの違い

GroverはFのみ11件・Dのみ6件、QPEは8件・2件、IQFTは6件・2件だった。一方、Bernstein–VaziraniはFのみ2件・Dのみ9件、DJ constantは2件・8件だった。モデル×タスクの内訳はcomparisons.csvに保存した。タスクに含まれる初期失敗のモデル・原因構成が異なるため、タスク名だけから最適介入を決めない。

## 保存コードと履歴の確認

84例すべてについてF/D各roundの評価段階・失敗分類・コードhashを保存し、うち次の4例のコードを静的に確認した。新規生成、コードの実行、評価のやり直しは行っていない。頻度による典型例の選定ではなく、観測された変更を説明する例である。

### 構文エラーの修正

case ID `1a8625f0c66ec4df`：qwen3.5:9b、T5_Grover_11、base seed 19、Fのみ救出。

baselineは閉じていない三重引用符で構文解析に失敗した。Fのround 1は構文解析可能な回路生成コードとなり、保存評価でL3成功した。Dはround 1〜3も構文エラーだった。

### importと回路APIの修正

case ID `05bf2d436b25b19d`：qwen3.5:4b、T3b_DJ_balanced、base seed 7、Dのみ救出。

baselineはCNOTGateのimportに失敗した。Dの最終roundではCNOTGateのimportを除き、回路操作をcxとし、Aerをqiskit_aerから取得した。保存評価はL3成功。Fは後続roundでもimport・回路APIの失敗を残した。途中で別の失敗を経てから成功しており、初回修正だけでは救出していない。

### 一つのAPI修正後に別の失敗が残る例

case ID `042375a50346c20c`：qwen3.5:4b、T3b_DJ_balanced、base seed 19、Fのみ救出。

baselineはQuantumCircuitのcnot属性がなく回路構築に失敗した。Fのround 1ではcxを使用し、保存評価でL3成功した。Dもcxへ変更したが、後続でシミュレータのimport失敗を経て、最終roundはAerJobの結果取得手順の誤用で失敗した。最初のエラーを解消することと、最終評価の成功を区別する必要がある。

### 出力不一致と古典ビットの表現

case ID `2cf271244f2ea0cd`：gemma4:e4b-it-qat、T8_QPE_001、base seed 16、Fのみ救出。

baselineとF round 1には未使用の古典ビット3個があり、保存された評価分布は1010000に確率1であった。F round 2は古典ビットを持たない回路へ変更し、評価分布は1010に確率1、L2距離は約4.44e-16でL3成功した。期待分布は1010である。Dは最終まで出力不一致を残した。この例のwrong_outputには、未使用古典ビットと評価用測定追加による出力表現の違いが関係していると考えられる。量子アルゴリズムの論理誤りだけとは解釈しない。原判定を保持し、評価器のreadout処理への感度は別の検討課題とする。

## 次の確認事項

Fのみ／Dのみの残りの例にも、同じ失敗を繰り返した場合と、初期エラーを解消して別の失敗へ移った場合がある。分類・到達段階・修正回数を合わせて見て、API修正、関数形式の維持、出力表現、回路論理を分けて確認する。

今回の差はschema 2.0/2.1の診断文処理差、実施時期、seedブロックを含む記述的な観測である。特にQPEの確認例は、出力不一致をすべて量子論理の誤りへ帰属させないための根拠となる。原記録と判定は保持し、追加追試や評価器変更の必要性を検討する。一般的優劣、因果効果、統計的有意差は確定しない。
