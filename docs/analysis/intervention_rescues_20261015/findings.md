# 介入による救済の観測結果と解釈

本研究では、初期生成に失敗したコードを各介入がどの程度救済できるかを調べる。課題仕様に沿って整備した評価を共通に用い、必要な部分追試を反映した経路を分析する。評価器の変更履歴は方法の補足に置き、介入による救済を主結果とする。数値の出典は[固定集計](results_snapshot.json)、層別の分母と件数は[修正介入の全表](repair_summary.csv)である。

## 主要な観測

1,000初期組のうち545組が初期失敗だった。同一初期コードを共有するR・F・Dの救済は、それぞれ96/545組（17.6%）、183/545組（33.6%）、180/545組（33.0%）。本対象ではFとDの救済率がRを上回った。FとDの差は3組、約0.6ポイントであり、全体率だけからどちらかを推奨する根拠にはしない。初期成功455組は3条件とも修正せず保持されているため、修正型で退行0組なのは成功時に停止する設計と合わせて解釈する。

全体率は初期失敗545組を分母とする合算値であり、モデル別救済率の単純平均ではない。例えばgemma3の初期失敗190組がこの分母に含まれる。各モデルには200初期組があるが、介入対象となる初期失敗数は異なるため、全体率とモデル別率を併記する。

## FとDは救済する対象が異なる

共通救済140組、Fのみ43組、Dのみ40組、双方未救済322組だった。FまたはDの少なくとも一方で救済されたのは223/545組（40.9%）。これは結果を見て選んだ場合の観測上の集合であり、実行前に介入を選べる方策の成功率ではない。

モデル別ではgemma4でF 48/62組（77.4%）・D 38/62組（61.3%）、qwen3.5:4bでF 78/162組（48.1%）・D 90/162組（55.6%）と大小が入れ替わる。qwen3.5:9bはF 33/66組・D 28/66組、qwen2.5-coderは双方23/65組。gemma3はF・Dとも1/190組だった。モデルの一般的能力や学習方式への帰属は行わず、対象条件での使い分けを検討する手がかりとする。

## 初期失敗類型による違い

import_errorではF 58/271組（21.4%）・D 72/271組（26.6%）で、Fのみ8組に対しDのみ22組。build_errorではF 76/126組（60.3%）・D 68/126組（54.0%）で、Fのみ19組・Dのみ11組だった。wrong_outputではF 24/65組（36.9%）・D 18/65組（27.7%）。失敗類型によって観測された救済率と片側救済の傾向が異なる。

この集計の分類はすべて介入前のbaselineに固定した。失敗類型の構成はモデル・タスクと関連するため、「importならD、構築ならF」という運用規則をこの表だけで確定しない。モデル×失敗類型の分母を確認し、Fのみ43組・Dのみ40組の修正履歴を調べることが次の分析になる。qubit_count_mismatchは3組、unknown_errorは1組のため、率による一般化は避ける。unknown_errorは保存された分類名であり、原因注記は[追試記録](../reevaluation_followup_20261015/unknown_failure_triage.csv)に分けて保持されている。

## 修正回数の寄与

Fの救済は1回目112組、2回目の追加43組、3回目の追加28組。Dは108組、39組、33組だった。観測経路を2回で区切ると、3回までの救済のF 155/183組（84.7%）、D 147/180組（81.7%）を保持する一方、28組・33組を失う。3回目直前まで未救済だった組に対する追加救済はF 28/390組（7.2%）、D 33/398組（8.3%）。この分母は全初期失敗545組とは異なる。

同じ最大3修正の履歴を区切った観測であり、上限別の独立実験ではない。生成コストをこの版でまだ比較していないため、2回または3回を費用面で最適とはしない。旧評価に基づくコスト・上限分析の数値は現在の救済数と混ぜない。

## Pの位置づけ

Pは生成前に注意事項を与える独立生成であり、失敗コードの修正ではない。baseline失敗に対応する成功124/545組（22.8%）と、baseline成功に対応する失敗106/455組（23.3%）が観測された。Pの最終成功473/1,000組とbaselineの455/1,000組との差は18組だが、改善と悪化の両方が含まれる。R・F・Dの修正による救済率と同一の作用として解釈しない。

## 発表での主張と次の作業

主張の中心は「実行結果提示と自己デバッグは、今回の対象では自己見直しより多くの初期失敗を救済した」「両者の全体救済率は近いが救済対象が異なり、モデルと初期失敗類型により内訳が変わる」の二点とする。統計的有意差や一般的な最適介入は主張しない。

次は今回の対応記録からFのみ・Dのみの修正履歴を確認し、救済へ至った具体的変更を記述する。追加コストと3回目継続の分析も現行の到達経路で更新する。発表資料には主要結果、モデル別、初期失敗類型別、F/Dの重なりを優先して掲載する。

保存prefixと新規suffixを組み合わせた経路の由来、元3実験の設定・seedブロック・schema差、主判定の被覆範囲は[方法と出典](README.md)を参照。全件を初回生成からやり直した実験ではなく、今回の集計作業で新しい生成・生成コード実行は行っていない。
