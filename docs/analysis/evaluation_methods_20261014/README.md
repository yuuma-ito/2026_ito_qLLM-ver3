# 5000件再評価前の評価方法点検

2026-10-14に評価器・全10タスクを点検し、手作り／既存mockの確認用回路38例、独立した期待値計算3例、閾値付近の二項サンプリングを調べた。過去のLLM生成コード5,000件の実行・再評価はまだ行っていない。

## 結論

分布のTVDと、全体位相を除いた状態ベクトル距離は、対応する出力を比較する方法として適切である。ただし状態ベクトルの位相補正に符号誤りがあり、再評価前に修正した。期待値を定義するQFT・逆QFT・Ansatzは独立した計算とも一致した。

現在のL3は「出力一致＋粗い構造条件」の判定であり、指定された状態・アルゴリズム・ゲート列をすべて満たす保証ではない。5,000件の比較では、主判定をこの定義でそろえたうえで、追加の状態・構造検査を別列に記録する方針を推奨する。補助検査で旧主判定を無断で置き換えない。

## 確認した実装上の問題と修正

| 項目 | 修正前 | 修正後 |
| --- | --- | --- |
| 全体位相 | QFT・逆QFT・Ansatzの正しい状態にπ/4・π/2を加えた計6例がL2未達 | 6例すべて成功。相対位相を変えた3例は不合格を維持 |
| サンプリング | simulator・transpileのseedが未指定 | 両seedを42に固定。shotsは8,192を維持し、manifestに記録 |
| barrierの構造判定 | Bellにbarrierを6個加えるとゲート数上限超過でL3未達 | 構造判定のゲート数からmeasureとbarrierを除き、成功 |
| 未束縛パラメータ | unknown_error | build / interface_mismatchとして分類 |
| 状態ベクトル回路内の測定 | unknown_error | evaluate / interface_mismatchとして分類 |
| ゲート数範囲外の構造 | unknown_error | evaluate / interface_mismatchとして分類 |

評価器の版は `evaluation_policy_v3` とした。測定先に基づく量子ビット順の復元も保持する。旧実験の未完了データへ新しい版で追加生成しない防止処理は、版変更にも適用される。

`gate_count`の保存値は従来どおり回路の命令数であり、構造判定用のゲート数とは異なる。今回のbarrier除外は構造判定側の変更である。

### 全体位相の補正

内積を `actual† expected` としたとき、actualをそろえる補正は `exp(+i arg(inner))` である。旧コードは負符号だった。同じ状態に全体位相π/2を加えると旧距離は2になったが、修正後は数値誤差程度になる。

独立確認には、正規化状態の距離 `sqrt(2 - 2 abs(actual† expected))` を使った。[QiskitのStatevector仕様](https://qiskit.qotlabs.org/docs/api/qiskit/qiskit.quantum_info.Statevector)でも、全体位相を除いて同値性を確認することが定義されている。相対位相は物理的な違いであり、除去しない。

## 主判定の限界

### 測定分布は相対位相を確認しない

Bellのプラス状態とマイナス状態、GHZのプラス状態とマイナス状態は、計算基底の測定分布が同じである。今回の確認では状態のfidelityは0だったが、現行の分布タスクは両方をL3成功とした。

TVDの実装の誤りではなく、測定分布だけを正解とする評価対象の限界である。「Bell状態を作れた」「GHZ状態を作れた」とまで解釈する場合は、状態ベクトル・密度行列のfidelityなどの補助評価が必要になる。

### 一入力の出力とゲート数だけではアルゴリズムを保証しない

Groverの要求された手順を使わず、Xで11を直接用意してidentityを6個追加した回路も、出力とゲート数が一致してL3成功となった。逆に、正しいBell・GHZを1個の合成ゲートへ包むと、出力は一致してもゲート数下限でL3未達となる。

ゲート数範囲は粗い代理指標であり、アルゴリズムの正しさや同等な回路の構造を保証しない。QFT・逆QFTも固定入力001の出力を評価しており、一般の入力に対する変換全体の検証ではない。Ansatzの固定角・順序も、状態一致とゲート数だけでは厳密には確認できない。

再評価ではL2とL3を分けて報告し、「アルゴリズムを正しく実装した率」と呼ばない。将来の厳密な構造検査では、合成ゲートの展開、パラメータとゲート順、複数入力での作用などをタスク別に定義する必要がある。

### 測定禁止の指示と構造メタデータ

共通プロンプトは回路内測定を禁止しているが、現在の10タスクは `measurement_required` を明示しない。正しいBellへ全測定を加えた確認例はL3成功となった。現在は許容された測定から分布を読む仕様であり、プロンプトの全要件を強制する評価ではない。

測定禁止を再評価に追加すると成功の定義も変わるため、今回の実装修正とは分ける。保存コードの測定有無を補助列に記録し、必要なら別の厳格評価として比較することを推奨する。

## 距離と閾値

TVDは `0.5 * sum(abs(actual - expected))` で、確率分布の違いを比較する定義として適切。閾値は全タスクで0.05、判定は厳密に「距離 < 0.05」。状態ベクトル距離とTVDは異なる量なので、同じ0.05が同じ厳しさを表すわけではない。正規化状態の距離0.05は、最適に位相をそろえたfidelityが約0.9975を超える条件に対応する。

二値分布の二項サンプリングをseed 42、8,192 shots相当、各10,000回で調べた。

| 真のTVD | 標本TVDで成功した割合 |
| --- | ---: |
| 0 | 100.00% |
| 0.040 | 96.45% |
| 0.048 | 63.98% |
| 0.050 | 49.68% |
| 0.052 | 35.51% |
| 0.060 | 3.35% |

これは二値分布の例であり、全タスクに同じ割合が当てはまることを意味しない。seed固定は同じ環境での再現性を改善するが、閾値近辺の統計的な不確かさを除かない。[Aerの仕様](https://qiskit.github.io/qiskit-aer/stubs/qiskit_aer.AerSimulator.html)に基づいてseedを指定した。再評価では距離そのものも保存し、閾値近辺の例を別seedや厳密確率による補助確認の対象にする。

## 期待値と段階の確認

QFT・逆QFTは独立したFourier行列の入力001の列、Ansatzは独立した振幅更新で検証し、3タスクの期待値と一致した。残る7タスクの分布は手順の解析と正しいmock回路の出力を照合した。正しいmock10例はすべてL3成功、明らかに誤ったmock10例はすべてL2未達だった。

L0はコード実行と必須関数のインターフェース確認、L1は出力取得、L2は出力一致、L3はL0・L1・L2と構造条件の論理積である。L0が成功しても回路構築や出力取得に失敗する場合がある。生の構造判定だけを独立した意味的成功として数えない。

## 5000件の再評価への推奨

1. 主判定には修正済み `evaluation_policy_v3` と元タスクの定義を使い、旧判定・全修正履歴を保持したまま別保存先へ記録する。
2. 分布タスクに状態の補助検査、測定の有無、ゲート数、閾値からの距離などの列を追加し、主判定と分けて報告する。非ユニタリ回路などで補助検査ができない場合は「未評価」とする。
3. 生成コードはプロセスを分け、時間・資源制限を設けて実行する。現行 `evaluate` は同一プロセスのexecであり、無限ループなどを止める機能を持たない。再評価用の実行処理で用意する。
4. 過去の修正経路は旧評価器のフィードバックで選ばれたことを明記する。旧版なら停止したroundを新版で成功と扱っても、その後の生成を想像して補わない。

補助検査と隔離実行の設計は5,000件の実行前に必要な次の作業であり、今回の点検では本再評価を開始していない。学会原稿の結果表も元の数値を保持する。
