# 3回目の救出例から確認した継続条件

検証済み3実験5,000件の固定結果から、2回目までL3未達だったF 416件・D 415件を比較した。3回目の救出はF 25件（6.0%）、D 24件（5.8%）。共通3組を含むため、49条件記録は異なる初期例46組に対応する。

| 3回目直前の失敗 | F：救出／実施 | D：救出／実施 |
| --- | ---: | ---: |
| import_error | 9/224（4.0%） | 9/210（4.3%） |
| wrong_output | 9/86（10.5%） | 2/79（2.5%） |
| build_error | 3/47（6.4%） | 8/55（14.5%） |
| syntax | 3/35（8.6%） | 5/43（11.6%） |
| interface_mismatch | 1/19（5.3%） | 0/26 |
| qubit_count_mismatch | 0/5 | 0/2 |

初期失敗類型と直前の類型は異なる。前者ではFのimport救出11件、Dは12件だが、直前のimportからの救出は各9件だった。分類の変化も修正履歴に残した。

モデル別ではqwen3.5:4bがF 12/103件・D 12/94件、gemma4がF 7/24件・D 2/26件。gemma3は両条件とも0/198件だった。直前importの全体率にはgemma3のF 152件・D 156件が含まれる一方、qwen3.5:4bではF 7/53件・D 9/35件を救出しており、全体率だけで停止条件を決めるとモデルによる違いを隠す。

タスク別の救出数ではFはQFT 6件、Grover・IQFT各4件、DはBV 7件、DJ balanced・QFT各5件が多かった。[全表](README.md)とthird_round_summary.csvに未救出例も含めたタスク・モデル×タスク・出典別分母を保存した。

| 停止候補 | F：失う救出／全救出 | D：失う救出／全救出 |
| --- | ---: | ---: |
| round 1・2が同じ失敗分類なら停止 | 18/25 | 15/24 |
| 初期からround 2へ段階上昇した例だけ継続 | 19/25 | 21/24 |

同じ分類を繰り返した例や、初期から評価段階が上がらなかった例からも救出が生じた。この2つの単純な停止候補は多くの追加救出を失う。同じ分類はコードが同一であることを示さず、段階が不変でも修正が無意味とは判定できない。省かれるtokens・時間との交換関係はcandidate_rule_checks.csvに保存した。

継続条件を検討する次の候補は、モデルと直前の失敗類型を組み合わせ、追加救出と生成コストを比較すること。今回の数値は同じ観測済み履歴による探索的比較であり、停止方策の採用には別のseed・タスクでの検証が必要である。少数例、実施時期、schema 2.0/2.1の診断文処理差、seedブロック、要求時間のサーバ負荷を限界として保持する。

49救出記録の4段階、計196行の履歴と元record・コードhashを公開した。新規生成・生成コードの再評価は行っていない。出典・保存設定・固定スナップショット・前段分析のhashはmanifest.json、照合結果はsanity_report.jsonに記載する。生成コード・生の例外文・秘密情報は含めない。
