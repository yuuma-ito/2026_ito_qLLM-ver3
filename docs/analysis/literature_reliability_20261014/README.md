### 原文から採用する論点

- **R1の記述**：入力生成、終端オラクル、距離・統計、同値性、既知の不具合やmutationを整理する。**本監査への適用**：固定入力だけの検査、閾値、同値変換への感度、検出できない変異を区別する。
- **R3の記述**：仕様の抽象化、オラクルの健全性・完全性、派生オラクルとメタモルフィック関係を扱う。**本監査への適用**：測定分布一致を状態・アルゴリズム一致と取り違えず、オラクルの適用範囲を記載する。
- **R5の記述**：実行テストによる機能的評価、独立候補のpass@k、ホスト・ネットワークを保護するsandboxを扱う。**本監査への適用**：実行評価の隔離を要求し、修正履歴をpass@kと呼ばない。
- **R6の記述**：同一モデルによる生成・feedback・refineを別段階に置き、履歴と停止条件を使う。**本監査への適用**：現在のRの手順差と呼び出し予算を明記し、原論文の再現と区別する。

## 新たに発見した不具合と修正

### 非ユニタリ操作の分岐による主判定

Bellを用意してq0だけをresetすると、独立した密度行列は `diag(0.5, 0, 0.5, 0)`、目標00とのfidelityは0.5になる。ローカルの旧 `_run_statevector` を12回実行すると、目標00とのfidelityが1の分岐7回、0の分岐5回を得た。これは実験全体の頻度推定ではなく、同じ回路で異なる主状態を比較できることの再現である。

**修正**：主状態ベクトル評価は `Operator(qc)` で演算子を作り、ユニタリであることを確認して全ゼロ入力に対応する列を返す。非ユニタリ・古典操作は `ReadoutError` により `evaluate / interface_mismatch` とする。合成instruction内のresetも拒否し、ユニタリなStatePreparationは許可する。版を `evaluation_policy_v4` とし、manifestへ主状態ベクトル方針を記録した。

これは本監査が選んだ保守的な適用範囲であり、Qiskitが非ユニタリ操作を一切評価できないという意味ではない。全体initializeで確実な純粋状態を作る回路も主判定から除外するため、除外理由を記録し、必要なら密度行列による別の補助指標を用意する。旧版との比較ではこの判定方針変更を明示する。

### 重複・破損した記録の再開

通常の `load_existing` は、rowsに重複を残したままkeysをsetにしていた。**修正**：同じrecord keyが現れたら停止する。壊れたJSONLにも行番号を伴う拒否を行い、自動で削除・修復・上書きしない。下書き起動と完了待機のgateも、読込拒否をblockedとして扱う。

### 旧新オラクルの混合を防ぐ比較条件

統合用signatureは評価器版とsampling条件を含んでいなかった。**修正**：evaluator_version、evaluation_sampling、statevector_policyを比較へ追加し、不一致を同一条件の統合・追試として通さない。旧manifestで版がない場合はlegacy_unspecifiedとし、旧結果をv4へ書き換えない。

## baselineとSelf Refineへの適用上の注意

保存済みB/R/F/Dの共有初期は1,000対応組で一致した。これは初期条件をそろえた比較の裏付けになるが、同一生成予算の比較ではない。R/F/Dは最大3回の追加生成、Pは予防文付き独立初回生成である。追加tokens・要求時間と結果を併記し、単純な独立再生成を同予算で行う対照条件は現データにないと明記する。

R6のSelf-Refineは自己feedbackとrefineを分けて生成し、履歴を追加する。現Rは前回コードの自己点検と修正を1要求で行い、全履歴を渡さず、外部評価器のL3で継続・停止する。外部診断の内容はRへ渡さないが、継続の選択自体は外部判定に依存する。Self-Refineそのものの再現結果ではなく、自己点検修正の派生条件として記述する。

R5のpass@kは独立に生成された候補の設定に対応する。外部結果を利用する適応的修正の「一度でも成功」を、そのままpass@kと呼ばない。最初の成功、途中での成功、最後の成功、成功後の退行を別の列にする。

旧評価器で成功して停止した履歴には、それ以降のコードがない。新オラクルで旧成功が失敗になっても、続ければどうなったかは不明である。旧評価器で失敗して続いた履歴に新版の途中成功が見つかっても、記録済みの後続を勝手に削除しない。主比較は保存された最終コードの再採点、履歴のever/firstは別指標とする。

## 統計とコストに関する判断

TVD 0.05は距離の閾値であり、p値0.05の検定と同じではない。状態距離0.05も同じ誤り率を保証しない。seed固定は再現性のためで、モデル出力やshotの不確かさを消すものではない。境界例には別seed・shots、可能なら厳密確率を補助情報として保存する。

本監査のWilson区間は二項模型の独立反復へ適用する例である。5,000件を独立としてそのまま区間を付けない。条件別の対応組、モデル・タスク・seed・出典別の分母を保持し、比較は対応を考慮する。一般化にはtask数10の限界もあり、cluster bootstrap等の具体的設計は本プロジェクトの提案として事前に決める。現在の記述的結果に統計的有意差を追加したわけではない。

再評価のコストには、コードhashで共有初期の重複実行を避けたユニーク評価数、補助検査数、shots、wall/CPU時間、timeout・再試行の費用を含める。LLM再生成を行わない方針でも評価コストは0ではない。Operatorは行列を作るためO(4^n)のメモリを要する。現タスクの小規模回路には適用できるが、生成コードが大量の量子ビットを返す場合への上限は隔離executor側で必要。

| 完了検証と集計 | 元データは整合。再評価結果を集計する処理は未検証 | 予定キー・round・hash・ever/final・条件別集計を照合 |
| コストと境界例の計画 | 監査の費用・感度を記録 | 同じ環境で小規模dry runを行い予算・境界方針を固定 |

専用executorを作る場合も、単なるsubprocessはセキュリティsandboxではない。R5のgVisorを必ず使うという意味ではなく、同等に必要なホスト・network保護を実環境で検証する。主評価失敗と基盤障害を区別し、未解決の基盤障害を成功率の分母へ黙って含めない。

## 残る限界

- R4本文は未確認。他文献の紹介で内容を埋めない。
- 主分布は相対位相を、粗い構造条件はアルゴリズムを完全には検査しない。
- ユニタリ限定は安全側の仕様変更で、正しい非ユニタリ状態準備も主判定から除外する。
- 独立した数式は使うが、回路構築・シミュレーションにはQiskit依存が残る。
- 82検査と6 mutationは選択された小さな集合で、全不具合への健全性・完全性の証明ではない。
- 固定入力、固定パラメータ、少数task、異なる出典・旧feedbackの経路選択による限界が残る。
- 5,000件の実行時間、基盤障害率、再評価の成功率は未測定である。
