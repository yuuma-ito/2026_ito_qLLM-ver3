# 主判定・補助判定と課題仕様の照合

対象は固定された evaluation_policy_v4 / coherent_oracles_v2 の全9,517保存round。主L3と補助の合否は同一の定義ではない。集計は主L3合格・補助passが2,956 round、主L3合格・補助failが1 round、主L3合格・補助適用外が1 round。主L3不合格・補助passは0 roundであった。適用外はpassやfailへ置き換えない。

主L3合格・補助failの `325c64f1128273e72844a4d33dd3ead262254e5458e9fe3af51947b9442a3fcf:0` は5モデル出典のgemma3:4b／T7／base_seed 10／P。保存コードと課題文を確認した。指定の入力|001⟩を作る際に、0のままのqubit 1・2へZを追加している。その後は正しい逆QFTであり、固定入力の出力には影響しない。一方、任意入力に対する準備＋変換ユニタリは標準回路と異なる。したがって固定入力の主判定成功と、より厳しい全ユニタリ補助検証の失敗は両立する。補助失敗だけで主判定や部分追試対象を変更しない。

主L3合格・補助適用外の `b307e1f24d6f322880337141c093c7e67e7598a0dfce33cb5deeec4197522860:2` は3モデル出典のqwen3.5:4b／T3a／base_seed 9／D／round 2。正しい定数オラクルの回路にmeasure_allを加えている。分布は主判定に合格するが、未測定回路を必要とする状態・全ユニタリ補助検証は適用外になる。共通systemプロンプトは測定を禁止しているため、厳密なプロンプト遵守まで保証された例とは扱わない。

この測定指示の被覆不足は[再評価前の評価方法監査](../evaluation_methods_20261014/README.md)と[修正後の監査](../evaluation_methods_after_fix_20261014/README.md)でも既知の仕様上の限界として記録済みである。現在のTaskメタデータは測定禁止を明示しておらず、v4の主L3はプロンプトの全条件を強制する判定ではない。今回の固定評価profileへ厳格な測定禁止や任意入力ユニタリ一致を追加すると成功の定義が変わるため、主判定を途中変更しない。別の厳格評価を実施するかは次の課題とし、本作業で追加の全件生成を行わない。主補助が一致している例についても、プロンプト全要件の網羅的検証が済んだことを意味しない。

モデル生成コードはこの文書へ掲載せず、出典・保存設定・コードhashは設定manifestと全round監査へ残す。

部分再実験の途中確認：3モデル出典のqwen3.5:4b／T5_Grover_11／base_seed 4／D、ケース `c9d9095bd65eb8ab9e0721ebaeaa98f15a8150b16df8dbc502b8f3eabde46b36` の新round 3でも、主L3合格・補助適用外となった。保存された新コードを確認し、build_circuit内のmeasure_allが原因と確認した。これは上記の既知の測定禁止指示の被覆限界であり、主v4を途中変更せず、補助をpassへ置き換えず、主L3合格で停止した。新suffix全体の適用外件数は最終のpartial_auxiliary_summary.csvを参照する。
