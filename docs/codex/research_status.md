# 研究状況の一覧とSlack報告

研究状況の一覧を更新するには、リポジトリで次を実行します。

```bash
.venv/bin/python -m scripts.research_status
```

一覧は `.cache/research_status/status.md`、集計値は同じ場所の `status.json` に保存します。Markdownを開くと保存設定と実験レポートに移動できます。cron設定には5分ごとの更新を含めています。更新ログは `logs/research_status.log` です。ネットワーク接続やモデル生成は行いません。表示のみで観測履歴を更新しない場合は `--dry-run`、出力先を変える場合は `--output-dir` を使います。

一覧には、状態、記録件数、前回観測からの増分、処理速度、記録完了までの概算時間、既存の検証レポートの判定、要確認事項を表示します。実行中を先頭に表示し、`configs/reviewed_experiments.json` に記載された確認済みの過去実験は、再開中を除きMarkdownから省きます。JSONには残します。未対応形式や記録不整合も省略せず、読取失敗として表示します。

通常の実験とB4独立実験は予定レコード数を使います。通知文アブレーションと要因パイロットは専用の `progress.json` にある要求数を使い、最大要求数を「上限」と表示します。これらの要求数は成功後の打切りで上限に達しないため、ETAを計算しません。現在の対応範囲以外は保存設定の確認を促します。

速度は同じ設定・同じ実行プロセスで、60秒以上離れた観測間の増分から求めます。初回、再開直後、件数減少では比較しません。停止、停滞、要確認事項がある場合や進捗がない場合に完了見込みを出しません。モデルや条件ごとの処理時間が違うため概算です。検証・資料作成・公開に必要な時間は含みません。sanityやautomation reportは既存の判定を表示しており、この一覧の更新で再検証したものではありません。

Slack定期報告は日本時間0・3・6・9・12・15・18・21時です。`--only-active` により実験稼働中のみ送信します。全実験の定期報告には前回の送信成功時からの差分を表示します。送信成功とは既存の配送処理の受理であり、メール経路ではSMTP受理です。Slack着信を保証するものではありません。比較用の履歴は `.cache/research_status/notifications.json`、一覧の履歴は `dashboard.json` に分けます。初回送信は比較なしです。個別の即時イベント通知と `--config` の通知は従来の形式を使います。

```bash
.venv/bin/python -m scripts.notify_progress --overview --transport email --dry-run
```

プレビュー・送信失敗では通知用の比較履歴を更新しません。一覧更新やプレビューを理由に実験を再開・追試しません。生成コード・秘密情報・任意のエラー本文を出力に含めません。キャッシュ内の一覧は運用情報であり、論文の固定出典には使わず、論文では対象の固定スナップショットと検証結果を指定してください。

スキル原本は `docs/codex/skills/research-status/SKILL.md` です。Codexのスキルディレクトリへ配置すると、研究状況の確認や通知の保守に利用できます。
