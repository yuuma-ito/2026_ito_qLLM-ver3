# 実験台帳・論文の数値照合・実験前チェック

状況一覧から、次の3つのレポートを開けます。いずれもモデルへの要求・生成コード実行・再採点・通知送信・Git操作を行いません。

| 用途 | コマンド | 出力 |
|---|---|---|
| 実験台帳の更新 | `.venv/bin/python -m scripts.research_ledger` | `.cache/research_ledger/ledger.md` と `ledger.json` |
| 卒論の数値照合 | `.venv/bin/python -m scripts.check_research_claims` | `.cache/research_claims/report.md` と `report.json` |
| 新しい簡易追試の計画確認 | `.venv/bin/python -m scripts.experiment_preflight --config configs/shared_five_models_quick.json --new-run` | `.cache/experiment_preflight/report.md` と `report.json` |

各コマンドの `--out-dir` で保存先を変えられます。運用用のキャッシュは公開・固定出典に使わず、共有する場合は対象を確認して別の固定先へ保存します。

## 実験台帳

`results/*/experiment_config.json` を自動検出し、`configs/research_registry.json` の目的・仮説・種別・親実験・採用資料の注記と統合します。固定再分析はregistryに別IDで登録します。元実験のファイルは変更しません。設定・manifestのSHA-256、評価器と診断文の版、生成時と再分析時の評価版をJSONに保持します。元のmanifestに版がない場合は未確認です。生成時manifestを指定しても、保存ファイルの記述を示すだけで生成履歴全体を再検証したことにはなりません。

過去の事前仮説は、後から結果を見て補いません。記録がなければ `hypothesis: null` とし、未登録として表示します。目的欄は既存の実験種別の説明です。登録ID重複や親子関係の循環はエラーにします。親実験・採用資料が見つからない場合は要確認にします。新しい実験は自動検出されますが、目的・仮説・採用資料はregistryへの登録が必要です。台帳はcronで5分ごとに更新します。

## 論文の数値・出典の照合

`configs/research_claims.json` が、固定CSVのSHA-256、対象Word、表の列名、集計行の選択条件、分子と分母、丸め、本文の対象箇所を指定します。CSVは全行を読み、指定条件に一致する行がちょうど1行あることを確認します。成功率を分子・分母から再計算し、Wordの対象表の全データ行と照合します。本文は登録した文脈の数値を検査し、対象箇所の削除・重複も不一致として扱います。Wordの書式で数値が複数のrunに分かれていても文字列を連結して照合します。

初期設定の範囲は、卒論Wordの条件別追加成功表・失敗類型表・B4本文4箇所です。固定出典は `measurement_ban_corrected_20261104` で、診断文v2の追試集計と混ぜません。source manifestに登録された出力のhashも検査します。原稿の変更で文脈が変わった場合も、検査を黙って省略せず不一致とします。本文の対応づけを見直してください。

検査結果は「根拠と一致」「不一致」「根拠不足」に分けます。終了コードは登録範囲の一致が0、不一致・根拠不足が1、設定不備等が2です。未登録箇所・図・PDFは未確認であり、論文全体の査読やrawからの再集計ではありません。出典を更新する場合は、hashだけを書き換えず、対象実験・評価版・分母・本文の対応を見直します。既存の `scripts.verify_public_research_evidence` は個別履歴CSVの件数や集合の算術も検査するため、固定資料の詳細確認には併用します。

## 実験前の計画確認

標準ハーネスの保存設定を `validate_config` で検査し、予定初期組・条件記録・モデル要求数の上限を計算します。修正条件の共有初期生成と、Pの独立生成を別に数えます。`pairs` の指定があれば、taskとseedの直積へ拡大しません。失敗による早期停止や成功後の打切りを含むため、要求数は上限です。

既存実験との重複はモデル・タスク・seed・条件IDの一致件数です。生成コードが同じである証拠ではありません。設定比較はモデル、介入と修正上限、温度、生成設定、評価器、診断文、prompt・評価器fingerprint、sampling、環境、モデルdigestを確認し、欠落を一致とみなしません。新旧評価や診断文の差異を表示します。未対応の専用schemaにはその実験の専用検査を使います。

出力先が存在する通常の新規実行は問題として扱います。`--new-run` は別ID・別保存先で追試する予定の宣言で、ディレクトリ作成や実験起動は行いません。実際の起動にも自動化ラッパーの `--new-run` が必要です。再開の場合は対象の保存設定を指定し、`--resume` を使います。保存設定が異なる再開や、既存のAPI障害・記録不整合がある場合は止めます。稼働中の実験がある場合も問題として表示します。

所要時間は、同じ対象組・比較条件で、自動検証済みの過去実験に壁時計時間がある場合のみ参考値を表示します。現在のモデルdigestは通常のローカル設定だけでは確認できないため、必要なら `--model-snapshot <リポジトリ内の保存JSON>` で `model_digests` または `shared_server.models` を含む記録を指定できます。これは過去の保存値に基づく宣言であり、現時点のサーバ状態の確認ではありません。根拠が足りない場合は時間を捏造せず「算出なし」とします。条件の違う実験を比例拡大した見積もりは行いません。

計画チェックの終了コードは実行を妨げる問題なしが0、要修正が1、未対応形式・設定不備が2です。0でも警告や未確認事項は残り得ます。サーバ到達性・API認証・モデルの現時点の状態は確認していないため、実行時の既存preflightも必要です。このチェック単体を実験実行の許可や論文に採用できることの証明にしません。
