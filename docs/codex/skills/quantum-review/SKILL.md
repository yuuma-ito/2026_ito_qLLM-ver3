# 量子記述・回路の技術点検

量子計算としての誤りと、意味は正しいが曖昧な表記を区別し、原稿の説明・数式・回路・コード・評価条件の対応を確かめる。投稿先への適合や研究の新規性の査読とは区別する。

## 対象と作業範囲

- 指定原稿の現行版と、対応する回路・課題仕様・評価器を必要な範囲で読む。PDFは掲載ページ番号を確認し、数式・回路図の指摘は画像でも確認する。抽出テキストの欠落だけで誤りと断定しない。
- 点検だけの依頼では原稿を変更しない。修正が依頼・承認されていれば、その範囲を生成元へ反映し、出力文書も更新する。同じ修正の承認を取り直さない。
- 自分が執筆した原稿の独立点検が必要な場合は、執筆履歴を渡さない別セッションまたは査読用エージェントに、対象原稿・必要な仕様だけを渡す。期待する指摘や修正案を先に教えない。独立点検ができなければ自己点検と明示する。
- 実験時の固定プロンプト、モデル出力の引用、原記録を説明文と区別する。問題を見つけても引用や実験記録を修正文へ置き換えず、注記と将来の設定変更を分ける。

## 技術的に照合すること

必要な項目を対象に合わせて選ぶ。すべての文書へ同じ補足説明を追加する必要はない。

- **状態と出力**：純粋状態のケットと測定結果の古典ビット列を区別する。測定結果の `00` に一律にケットを付けない。状態ベクトルの説明は純粋状態に限定し、混合状態や部分系を扱う場合は密度行列を確認する。正規化とBorn則の振幅・確率を照合する。
- **位相と同値性**：大域位相と相対位相を区別する。正規化した出力純粋状態の大域位相だけの違いを出力誤りとしない。ただし、制御演算へ組み込むと元演算の大域位相が制御枝間の相対位相になることがあるため、演算子の全体位相を文脈なしに捨てない。
- **回路**：初期状態、ゲートの作用順、制御・標的、回転角の単位・符号、逆演算、swap・補助量子ビットの役割から期待状態を追う。コードの記載順と行列積の作用順を対応づける。測定・reset・初期化などの非ユニタリ操作を、量子回路一般の誤りと扱わず、課題と評価方式への適合で判断する。
- **ビット順**：数式のテンソル積順、回路の線の順、SDKの量子ビット番号、古典ビットへの測定対応、表示ビット列を分ける。Qiskitの標準表示では右端がbit 0だが、独自の射影・読出し規約は仕様と実装を確認する。文字列の無条件反転を解決策にしない。
- **算法**：Bell/GHZ、DJ、BV、Grover、QFT/IQFT、QPEなどは、使われている具体的な入力・オラクル・位相・反復回数で照合する。特定の入力で正しいことを、算法全体の正しさや任意の入力への保証としない。
- **評価の射程**：計算基底の分布一致だけで状態・位相・エンタングルメントの一致を認定しない。状態ベクトル一致も単一入力なら演算子全体の同値性の証明ではない。有限shotsの標本変動と厳密な確率を区別する。期待値を同じSDKの参照回路から作った場合、その一致を独立した数学的検証と呼ばない。

## 根拠と確認方法

疑問のある物理・数学の主張は定義や短い導出で確かめ、APIやSDKの挙動は対象バージョンの公式資料・公式ソースと照合する。参考になる公式入口は次のとおり。リンク先を開いて確認してから根拠として使い、確認できなければ未確認とする。

- [IBM：量子状態・測定・Bell状態](https://quantum.cloud.ibm.com/learning/en/courses/basics-of-quantum-information/multiple-systems/quantum-information)
- [IBM：密度行列](https://quantum.cloud.ibm.com/learning/en/courses/general-formulation-of-quantum-information/density-matrices/density-matrix-basics)
- [IBM：Qiskitのビット順](https://quantum.cloud.ibm.com/docs/en/guides/bit-ordering)
- [Qiskit公式ソース](https://github.com/Qiskit/qiskit)

小さな回路は数式・行列で追跡する。実行が必要なら、読んで確認したコードを隔離した一時領域で必要最小限に検証する。保存済みのモデル生成コードを許可なく実行しない。モデルAPI呼出し、実機ジョブ、新しい研究実験や再採点は点検の依頼から自動的に追加しない。静的確認、解析計算、シミュレーション、全入力の証明を区別して記録する。

## 報告と修正後の確認

結果は重要度順に、該当ページ・節またはコード行、短い原文、問題となる前提と理由、最小の修正案、根拠を示す。「技術的誤り」「曖昧な記述・表記改善」「実験仕様・評価の制約」を分け、実験結果へ影響するかも説明する。誤りが見つからない項目を無理に指摘しない。未実施の検証を明示する。

修正した場合は、元の数値・固定記録・プロンプトを保ち、ケット・添字・符号・数式・回路図の表示と本文参照を再確認する。研究結果を変更したか、説明だけを修正したかを報告する。コミット・プッシュ・投稿は、利用者と対象リポジトリの指示に従う。
