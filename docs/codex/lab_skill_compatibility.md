## Codex での利用

この節はCodex向けの実行方法を補う。研究・査読の判断基準は下の元スキルを読む。
ユーザーが明示した目的・既存の承認・投稿先規定・対象リポジトリの指示を優先する。

- 呼び出しは `$スキル名` または用途を指定する日本語の依頼。Claudeの `/plugin` コマンドは使わない。
- このスキルの所在は `@SKILL_DIR@`。`<skill>` はこのパス、プラグインの `skills` は `@SKILLS_ROOT@` と読む。相対参照は元のSKILL.mdを起点に解決する。
- `Read`・`Glob`・`Grep`・`Bash`・`Edit` は、Codexで利用可能なファイル読取・`rg`・コマンド実行・編集機能へ読み替える。PNGは画像表示ツールで実際に確認する。
- Claude固有のモデル名を要求する箇所は、利用可能なCodexモデルを用いる。モデルを勝手に変更せず、能力差で未確認になる項目は報告する。
- 査読は原稿を書いた文脈から独立させる。白紙のCodexセッション、または履歴を継承しない査読用エージェントを使い、資料・規定だけを渡す。後者が使えなければ白紙セッションを使う。査読実行の依頼がある場合に限り、そのための委任を行う。
- 査読報告と原稿修正は区別する。レビューだけの依頼で原稿を書き換えない。執筆スキルの段階的承認は維持しつつ、ユーザーが具体的に指定・承認した修正について承認を取り直さない。
- 対象・持ち時間・提出様式はまず既存ファイルと会話で確認し、不明点だけをまとめて聞く。卒論へ修論専用の制約をそのまま適用しない。
- 機械抽出と画像確認の結果から判断し、未確認のページ・規定・文献は未確認と記す。事実・数値・評価定義・主張の範囲を保つ。
- `dellm review` を使う際は、新しい独立したCodex呼び出しとなる。公開可能な原稿だけを隔離した作業ディレクトリへ置く。既存の秘密情報を含むディレクトリをそのまま渡さない。`scan` はローカルだけで動く。
- 非公開の元スキル本文・チェック表は公開リポジトリへ転載しない。導入版の出典は `.lab-codex-source.json` で確認する。
